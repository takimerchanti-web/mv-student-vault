# MV Student Vault — Outcome Checklist

- [ ] **Responsive local-first application shell:** The app uses React, TypeScript, and Vite; all required runtime assets are same-origin and bundled; the responsive shell has a collapsible sidebar, contextual top bar, dashboard, consistent workspace layouts, mobile drawer behavior, semantic controls, visible keyboard focus, touch-friendly targets, useful empty/error states, and no page-wide horizontal overflow.
- [ ] **Onboarding, profile, dashboard, timetable, subjects, notes, tasks, habits, and files:** Profile data includes name, course/year, optional goals, and a clear local-storage explanation; dashboard summaries derive from saved data; timetable classes are editable with subject/day/start/end/room; subjects link notes/tasks/files; notes support create/edit/search/delete/autosave with accurate saved/error state; tasks support create/edit/priority/due date/complete/filter; habits support daily check-ins, date-aware history, and progress; Pomodoro supports timestamp-based start/pause/resume/reset and configurable sessions; files store actual bytes locally with organize/download/delete; settings expose profile, themes, scaling, motion, storage, and backup controls.
- [ ] **Persistence and backups:** IndexedDB stores structured data, projects, and actual file bytes; localStorage stores small preferences; quota/storage errors are handled; persistent storage is requested where supported; versioned backups contain Vault data, projects, and file bytes; restore validates version/structure, confirms replacement, and avoids destructive changes on invalid backups.
- [ ] **Themes, scaling, motion, and focus mode:** Exactly 14 selectable themes are complete and applied across pages, editors, canvases, menus, charts, inputs, dialogs, and focus states; Ctrl +, Ctrl −, Ctrl 0 (including Ctrl + = where appropriate) persist display scaling; reduced motion is respected and motion preference persists; engineering and presentation workspaces expose visible Exit Focus and Escape support.
- [ ] **Code Studio:** The workspace has explorer/tabs/editor/line numbers/syntax cues/run-stop/stdin/output/errors/autosave; a local Web Worker runs a real documented educational C subset with variables, arithmetic/comparisons, conditionals, loops, printf, scanf, examples, useful unsupported-syntax errors, execution/instruction/stdin/output limits, and genuine stop; the required interpreter disclosure is visible.
- [ ] **Logic Designer:** The workspace provides searchable recognizable device cards, tap/drag add, nodes, labeled clickable pins, wires, switches, output indicators, compatible connection checks, selection/movement/deletion/wire removal/save/navigation, local combinational evaluation, unsupported cycle detection, capped truth tables, explicit clock controls, documented latch/flip-flop semantics, invalid SR state indication, and reset.
- [ ] **Circuit Designer:** The workbench provides searchable categorized parts, draggable canvas, recognizable models, labeled terminals, wires, selection/value editing, local Simulate DC, real supported DC solving for ground/source/resistor/switch/LED, node voltages/branch currents, diagnostics for missing ground/floating/invalid/inconsistent/solver failures, and clear visual-only exclusions for capacitor/inductor/transistor/IC without secretly bridging nodes.
- [ ] **Presentation Studio:** The offline editor provides slide thumbnails, artboard, inspector, local themes, focus mode, slide create/duplicate/delete/reorder, editable text/shapes/tables/charts/images, selection/movement/resizing/deletion/layer ordering with accessible alternatives, local image storage, working preview navigation/transitions, and self-contained escaped JSON/HTML exports.
- [ ] **Offline readiness:** A service worker caches the production shell and same-origin assets including lazy workspaces and workers; updates do not unexpectedly reload unsaved work; accurate offline-ready state is visible; after first cache completion the production app reloads offline and each workspace remains functional; runtime makes no third-party requests.
- [ ] **Validation and delivery evidence:** Production build succeeds; actual behavior is tested for onboarding/persistence/backup/C interpreter/logic/circuits/presentations/themes/scaling/sidebar/focus/accessibility/mobile/offline/network privacy; setup instructions, architecture summary, actual results, supported C syntax, circuit limitations, and known gaps are documented without claiming untested behavior.
